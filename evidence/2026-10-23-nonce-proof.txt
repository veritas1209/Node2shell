Safety boundary
---------------
- Target fixed to 127.0.0.1:3000.
- Container port published on host loopback only.
- No arbitrary target, command, callback, or reverse-shell option.
- Fixed /n2s helper prints the current process nonce, then executes /usr/bin/id.
- Container used read-only rootfs, cap-drop ALL, no-new-privileges, PID/memory/CPU limits.

Independent repeatability batch
-------------------------------
A second fresh-container batch produced no nonce-bound proof in 16 attempts.
The verifier correctly returned result=not-verified with a non-zero exit status.
This confirms that the nonce change improves proof quality, not the underlying
ASLR hit rate. The released one-command harness therefore uses a 32-attempt
default budget and does not treat exhaustion as evidence that a build is safe.

Final one-command harness run
-----------------------------
After the 32-attempt default and explicit outcome classification were added,
`sh lab/run.sh vulnerable` reached rce-verified on attempt 8/32. Attempts 1,
2, 4, and 7 returned HTTP 400 without proof; attempts 3, 5, and 6 closed or
crashed without proof. Only attempt 8 returned the matching process nonce and
fresh id output. The script then removed its labeled lab container.

Interpretation
--------------
The vulnerable exact profile returned both the nonce obtained from that fresh
server process and fresh id output through the exploited request socket. Two
earlier crashes/empty responses were not counted as RCE. The patched build
rejected the same exploit input and retained the same health nonce.
